# 实验演进网页

本版提供本机只读网页：Agent 追加路线节点，研究者浏览分支、比较快照、查看引用与文件。它不执行实验，也不将记录者报告的结果自动认证为科学结论。

## 打开

项目根目录运行：

```bash
python scripts/route_viewer.py
```

打开 http://127.0.0.1:8765/ 。服务只监听本机，浏览器 URL 需使用 127.0.0.1。停止服务按 Ctrl+C；端口占用时使用 --port 8766。启动本身不创建实验记录。

首次想看合成演示：

```bash
python scripts/route_demo.py
python scripts/route_viewer.py
```

然后打开 http://127.0.0.1:8765/?namespace=demo 。

演示为五个节点：初始方案、补充资料/数据、两个平行分支、阶段总结。未采用分支也保留。教学文件与“报告已完成”标记均为预制内容，没有执行真实科学实验。

## 网页功能

- 左侧：按发展顺序排列路线图；可缩放、全图查看、滚动、搜索定位。
- 右侧：当前目标、方法、思路依据、参数、来源名称、数据与产物、变化理由和未决问题。
- 节点标签：相对前序节点的方法变更、参数调整、新增知识和新增数据。
- 下方比较：选择任意同实验两个节点，查看逐参数差异和固定版本的来源/数据变化；区分参数未设置、null 和已删除。
- 预览：点击依据后先检查文件哈希，再在网页内嵌预览；多份底层来源均可选择。
- PDF 使用浏览器内置预览；文本和 CSV 等直接显示；HTML/SVG 按文本显示，避免执行源文件脚本；XLSX 等提供下载，不冒充已解析。
- 外部来源 URL 可单独打开，不依赖网站允许 iframe 嵌入。
- real 与 demo 必须手动切换；真实库空缺不会回退到演示。

页面不会自动刷新；Agent 写入后点击“刷新记录”。网页没有编辑按钮和写入 API。

## Agent 怎样记录

推荐提示：

```text
$research-expert
请为实验 EX-001 建立演进记录。我授权你登记其路线快照和相关资料。
每次目标、方法、参数、文献或数据发生变化时，追加节点，
说明改变了什么、为什么改变，以及参考了谁/哪篇论文/哪项方法。
保留未采用分支，按计划与实际报告区分状态。
已有证据不足时标为未知，不补造历史或执行产物。
```

只有已核对的历史才能补录；无法确定的时间和事实保持未知。created_at 是登记时间，不是推断出的实验发生时间。可在 summary 中注明原记录时间和来源。

### 工具

| 工具 | 用途 |
| --- | --- |
| register_research_file | 归档 dataset 或 artifact；填写 title 与来源 origin |
| append_route_node | 追加不可覆盖的节点 |
| get_route_graph | 查询一个或全部实验的节点与发展关系 |
| compare_route_nodes | 比较同实验两个节点 |

这四个工具与原有 20 个 MCP 工具并存，总计 24 个。均默认 real，演示显式传 demo。

### 完整节点示例

以下字段示例引用的 SRC-001 必须已经通过 register_source 登记；参数和描述均为示意，不是实验方案推荐。

```json
{
  "node_id": "ROUTE-001",
  "namespace": "real",
  "data": {
    "experiment_id": "EX-001",
    "title": "初始方案",
    "stage": "start",
    "status": "planned",
    "goal": "明确本阶段要解决的问题",
    "method": "所选方法的名称",
    "rationale": "为什么选择该方法，参考了谁，哪些条件仍待核对",
    "parameters": {"example_parameter": 1},
    "parents": [],
    "knowledge": [{"id": "SRC-001", "version": 1}],
    "datasets": [],
    "artifacts": [],
    "change_reason": "首次建立路线",
    "summary": "计划草案，尚未执行",
    "open_questions": "待核对方法条件与数据"
  }
}
```

- stage 为 start / middle / end；开始节点没有父节点，其余阶段必须关联已存在父节点。
- status 为 planned / running / completed / failed / paused / abandoned。
- parents 是同实验节点的精确 id/version；可有多个父节点，表示汇合。为旧父节点新增另一个子节点即形成分支。
- knowledge 必须非空，可引用来源、方法或公式卡。原创思路可以先登记本地设计说明，并标明原创，而不是编造文献。
- datasets 引用 research_file 中 role=dataset 的文件；artifacts 引用 role=artifact。
- completed / failed 必须有关联归档产物。验证只检查文件与引用，不自动核对代码、运行环境、运行真实性或结果正确性。
- 每个节点填写当时完整的参数、知识与数据快照，不只填写增量。页面计算相对变化。
- 来源题名来自来源或知识卡 title；论文作者/出处可写入来源 origin，页面显示。未登记作者不自动猜测。

## 不覆盖历史

节点只能以新 ID 追加，无更新或删除接口。纠正旧记录时新增子节点，并在 change_reason 中说明纠正的内容；原节点仍保留。

资料与数据可登记新版本，但旧节点引用不会跟着漂移。新节点显式引用新版本后，比较区显示这次替换。新增论文不是自动采用依据，只有纳入节点 knowledge 才成为该节点声明的依据。

节点与文件作为报告记录保存在领域库，不写入旧真实库的 Observation / Decision。没有开放科学判断的自动接受或实验执行器。

## 本地与隐私

- 网页、API 和文件预览只由 127.0.0.1 提供，默认不允许跨站访问或网页写入。
- 仅通过已登记 ID/版本取文件，不提供任意路径下载接口。
- 所有原始资料与图数据仍在被 Git 忽略的 spatial-unit-kb/data/library 中；网页资源代码可以发布，研究内容不会自动上传。
- 文件上限 50 MiB；大数据可登记小型摘要或清单文件，明确实际数据所在位置与版本，但不能声称已经归档整份原始大数据。
- 停止写入后备份数据库和 files 目录；哈希只用于发现意外修改。
